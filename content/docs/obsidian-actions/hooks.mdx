---
title: Triggers and Hooks
description: Reference for when actions run and what to expect from each trigger.
---

Hooks determine when an action executes.

| Hook | Behavior |
|---|---|
| `manual` | Runs only when you trigger it as an Obsidian command. |
| `startup` | Runs when the plugin loads during Obsidian startup. |
| `interval` | Runs on a cron-style schedule. |
| `createFile` | Runs when the vault emits a file creation event. |
| `modifyFile` | Runs when the vault emits a file modification event. |
| `deleteFile` | Runs when the vault emits a file deletion event. |
| `renameFile` | Runs when the vault emits a file rename event. |

## Manual

Use `manual` while developing an action. It is the safest way to test code before enabling automatic execution.

## Startup

Use `startup` for maintenance tasks you want to run when Obsidian opens.

## Interval

`interval` actions require a valid cron expression. Example:

```text
* * * * *
```

This runs once per minute.

Use [crontab.guru](https://crontab.guru/examples.html) to validate schedules.

## File Hooks

The file hooks run when the vault emits the matching event. These hooks are useful for automations that should react to activity in the vault.

<Callout type="info" title="Current Context">
  File hooks trigger from vault events, but action variables still come from the current active file and editor context when those are available. Do not assume the action receives the event's file path directly.
</Callout>

<Callout type="warning" title="Operational Advice">
  Start with `manual`, confirm the action behaves as expected, then move it to `startup`, `interval`, or a file hook.
</Callout>
